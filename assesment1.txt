Problem 2

(a) In the worst case with 10 million users, linear search requires 10 million comparisons because it checks each username one by one, binary search requires about log₂(10,000,000) ≈ 24 comparisons since the search space halves each time, and hash table lookup requires only one comparison on average.

(b) Linear search has time complexity O(n) because the number of comparisons grows directly with input size, binary search has O(log n) because the list is divided into halves repeatedly, and hash table lookup has O(1) average time because access is done using a hash function.

(c) As n increases from 100 to 10 million, linear search comparisons increase linearly, binary search grows very slowly, and hash table lookup remains constant. This shows that linear search does not scale well, while binary search and hashing scale efficiently.

(d) At 50,000 searches per second with each comparison taking 1 nanosecond, linear search would take hundreds of seconds per second and fail, while binary search and hash table lookup take only milliseconds or microseconds and can easily handle the load.

(e) Although binary search is faster, it requires sorting the list first, which takes O(n log n) time. Sorting becomes worthwhile when the number of searches is large, specifically when the number of searches is greater than log₂(n), because the initial sorting cost gets amortized over many fast searches.
